# SpecFlow submission demonstration

## Three-minute story

An engineering lead turns meeting decisions into a reviewed sprint plan using Wispr Flow.

1. Open the Voice guide. Use your configured Flow shortcut with the brief focused. If eligible, connect Wispr Notetaker, search a meeting, preview it and explicitly use its notes.
2. Dictate: “Build an invoice approval system for our finance team. Use Postgres and Razorpay. Invoices with more than five percent variance need human approval in Slack. Ananya owns the backend. Mask bank details and keep an audit trail.” Wait for the cancellable countdown.
3. On Architecture, dictate: “Add a Redis retry queue before Razorpay and make Ananya P0 critical with eight points.” Show the new diagram branch and before/after receipt. This supported edit uses zero AI calls.
4. Say “Next step.” Review the specification, then say “Next step” again. Show sprint tickets with quoted source evidence or a proposal label. Open one ticket to edit its acceptance criteria and owner.
5. Continue to Deliver. Say “Approve plan,” then “Prepare Slack.” Inspect the preview. With a real authorized test webhook, confirm the exact displayed version. Otherwise stop at the preview and describe it as a draft.
6. Show GitHub issue draft links. Make another voice edit to demonstrate that approval becomes invalid for the changed version.

## Wispr features

Flow dictation supplies text to focused fields. Create a personal Flow snippet for recurring engineering defaults using the guide's copyable expansion. Add domain terms and teammate names to Flow's dictionary in Flow itself. Eligible Flow Command Mode edits selected text; SpecFlow's commands separately navigate and approve versions. Notetaker MCP reads selected meeting context after OAuth consent, and does not read dictation history.

## Verification and limits

Browser checks cover paste-triggered generation, sequential stages, Mermaid rendering, spoken-number edits, manual edits, review gates, version-bound confirmation, duplicate-send prevention, session-only credentials and desktop/mobile overflow. The browser delivery test uses a mock. Backend tests verify durable receipts without real messages.

Unit tests cover AI validation/fallback, quota throttling, encryption, source evidence and version changes. Authenticated Wispr meeting access and real Slack delivery require the user's connection; do not present these as live-verified until performed.

This hackathon prototype has individual browser workspaces. It does not provide enterprise identity, Jira sync, company-wide data access or shared editing. The displayed time estimate is based on word count, not a user study. Avoid confidential meeting content in the recording.
